# trendbot — инструкции для Claude Code

Эксперимент: поиск трендов TikTok через обычный браузер на компьютере пользователя и
создание похожего контента для его канала. **Без сторонних API** — только Playwright и
данные, которые сайт сам присылает в браузер. Сбор и статистика — код в `trendbot/`;
анализ, выводы и идеи роликов — твоя работа по отчётам.

Пользователь пишет по-русски — отвечай по-русски. Код, коммиты и комментарии в коде —
как в существующих файлах (комментарии и докстринги по-русски).

## Использование

Когда просят найти тренды, разобрать тренды или придумать ролики — следуй навыку
`.claude/skills/find-trends/SKILL.md` (команда `/find-trends`).

Команды:

| Команда | Что делает |
|---|---|
| `trendbot login` | открыть браузер на странице входа и ждать (до 15 мин), пока **человек** войдёт в окне; вход определяется по cookie сессии. Можно запускать самому — но логин и пароль вводит только пользователь |
| `trendbot collect [--feed N]` | лента «Для вас» → поиск по `keywords` → страницы `hashtags` → страницы частых звуков |
| `trendbot report [--frames]` | посчитать тренды, записать `data/reports/<дата_время>/report.md` и `trends.json`; `--frames` — снять кадры лучших роликов |
| `trendbot run [--feed N]` | `collect` + `report --frames` |

Все команды принимают `--config путь.toml` (по умолчанию `trendbot.toml` в текущей папке).
Запускать из корня репозитория.

## Правила (важно)

- **Капчи, проверки входа, защита от ботов — не обходить.** Не добавлять stealth-плагины,
  подмену отпечатков, решатели капч, ротацию прокси. Сборщик сам ждёт, пока человек
  пройдёт проверку в окне браузера; твоя задача — попросить пользователя.
- **Объёмы умеренные.** Не увеличивать `feed_videos`, число ключевых слов, частоту запусков
  и не уменьшать паузы без явной просьбы пользователя — аккаунт может получить ограничения.
  Автоматический сбор нарушает правила TikTok; пользователь знает об этом риске.
- **Чужие видео не скачивать и не перезаливать.** Кадры — только скриншоты плеера для анализа.
  Идеи роликов — адаптация формата, а не копия.
- **Контент от ИИ помечать** (метка AI-generated при публикации).
- `data/` — личные данные пользователя (профиль браузера с сессией TikTok, база, отчёты).
  Никогда не коммитить, не выводить содержимое `data/browser-profile`.

## Архитектура

```
trendbot/
  cli.py        команды login / collect / report / run
  config.py     Config: чтение trendbot.toml (разделы channel, collect, trends, frames)
  collector.py  Playwright: постоянный профиль, поведение «зрителя», перехват /api/ JSON
                и данных страницы, ожидание человека при капче, снятие кадров
  parse.py      извлечение Video / Sound / Hashtag из ЛЮБОГО JSON по форме объекта
  store.py      SQLite: videos + снимки статистики по времени (video/sound/hashtag_snapshots)
  trends.py     оценка роликов, звуков, хэштегов (чистая статистика)
  report.py     отчёт Markdown + JSON
tests/
  fixtures.py            JSON в форме ответов TikTok
  test_parse.py          парсер
  test_trends.py         оценка и отчёт
  test_collector_e2e.py  настоящий Chromium против локального макета сайта
```

Ключевые решения — не ломай их без причины:

- **Парсер не привязан к адресам эндпоинтов.** `parse.extract` рекурсивно обходит JSON и
  берёт всё, что похоже на ролик (`id` + `desc` + `author` + `stats`/`statsV2`), страницу
  звука (`musicInfo`) или хэштега (`challengeInfo`). Так он переживает смену URL.
- **В сборщике нельзя `time.sleep`.** Только `page.wait_for_timeout`: пока идёт `sleep`,
  Playwright не доставляет события ответов, и данные теряются (такой баг уже был).
- **Снимки, а не перезапись.** Каждое наблюдение пишется со временем; рост трендов
  считается между запусками (`Store.growth`).
- Формула оценки — `trends.score_videos` / `_finish`. Меняешь веса — обнови тесты в
  `test_trends.py` и опиши в коммите, почему.

## Тестирование

```bash
pytest                                   # все тесты (~30 с)
pytest tests/test_parse.py tests/test_trends.py   # быстрые, без браузера
```

- Сквозной тест поднимает локальный HTTP-макет TikTok и гоняет настоящий Chromium:
  лента (клавиша ↓ → `/api/recommend/item_list/`), поиск и хэштеги (прокрутка),
  страницы звуков, снятие кадров, режим дампа. К настоящему TikTok тесты **не** ходят.
- Нужен браузер Playwright (`playwright install chromium`) или путь к Chromium в
  `TRENDBOT_CHROMIUM_PATH`. Для видео в тесте нужен ffmpeg (`imageio-ffmpeg` или системный);
  без него проверка кадров пропускается.
- Перед коммитом: `pytest` зелёный. Любая правка сборщика — прогони сквозной тест;
  любая правка формата данных — добавь фикстуру.
- Проверка на живом сайте — только с согласия пользователя и маленьким объёмом:
  `trendbot collect --feed 5`, затем `trendbot report`.

## Когда TikTok поменял сайт (данных стало мало или ноль)

1. Попроси пользователя разрешить короткий отладочный запуск:
   `TRENDBOT_DUMP=1 trendbot collect --feed 5`
   (Windows PowerShell: `$env:TRENDBOT_DUMP=1; trendbot collect --feed 5`).
   Сырые ответы сайта попадут в `data/raw/*.json` и `*.html`.
2. Найди в них ролики (поиск по `playCount`, `diggCount`, `createTime`) и сравни с
   тем, что ожидает `parse._looks_like_video` / `_video`.
3. Урежь пример до 1–2 роликов, **убери личные данные** (ники, id, аватары своего аккаунта)
   и добавь как фикстуру в `tests/fixtures.py` + тест в `tests/test_parse.py`.
   Сначала тест должен падать, потом почини парсер.
4. Если сломалась навигация (лента не листается, поиск пустой) — открой браузер
   (`headless = false`), посмотри, что изменилось, поправь `collector.py` и макет
   в `test_collector_e2e.py`, чтобы он отражал новое поведение.
5. `data/raw/` удалить после починки.

## Как развивать дальше

Планы эксперимента (делать по просьбе пользователя, по одному шагу, с тестами):

1. Создание роликов по идеям: сценарий → картинки/текст на экране → озвучка → сборка
   вертикального видео 1080×1920 (ffmpeg).
2. Публикация через веб-интерфейс TikTok в браузере пользователя с подтверждением
   человеком перед кнопкой «Опубликовать» и меткой AI-generated.
3. Сбор статистики своих роликов и учёт её в следующих идеях.

Стиль кода: Python ≥ 3.11, стандартная библиотека где можно, новые зависимости — только
если без них никак (и в `pyproject.toml`). Маленькие модули, dataclass-модели, без
лишних абстракций.
